# Authenticated desktop acceptance

Prepared on ci/authenticated-desktop-tests; execution and pass results are unverified. On merge, the existing push-to-main/manual live workflow runs API tests and then desktop Chromium tests sequentially under the same concurrency lock and staging-live-tests environment. Required reviewers and main-only restrictions remain unchanged. This is not a deployment gate.

Thirteen desktop cases: real UI cloud save followed by fresh-context recovery; A/logout/B and modal clearing; delayed A cloud response after B activation; simulated logout failure; malformed account-local state and recovery download; simulated storage quota failure; cross-tab logout; six first/middle/last paycheck/excluded-bucket deletion cases. Fixtures use two real staging password sessions via Supabase setSession, not GitHub OAuth. No test login controls are added to the app. Dist is built from the current checkout plus the existing pinned upstream source, and served locally against only the staging backend. The existing guest suite is untouched.

Safety: dedicated empty test accounts only, same five existing environment secrets, no admin key. Each test checks both accounts are empty before creating fixtures with predetermined IDs and a run marker. Cleanup deletes only tracked IDs whose marker still matches and revokes test sessions. Missing or conflicting data fails the run, not an overwrite. Interrupted jobs can leave fixtures; manually inspect exact run-tagged records before cleanup. No credentialed traces, screenshots, videos, auth-state files, console output, error bodies or downloaded recovery JSON are uploaded. The custom reporter prints only test names and statuses, deliberately limiting failure detail.

Injected delay, failed logout and storage exceptions are fault-injection coverage, not evidence of an actual provider outage. Multi-tab failures must be reported, not skipped. True GitHub OAuth redirects/consent/MFA, expired-token UI recovery, conflicting unsaved edits across tabs and corrupt-cloud recovery are not covered by these cases. Passing the API fixture alone is not browser acceptance. Do not run credentialed code from an untrusted branch. Review and merge to main before running this protected workflow.
